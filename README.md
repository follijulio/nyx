# Nyx - GLOBAL

CLI for installing Neo-Brutalist components as editable files in your project.

## Development and usage

```sh
npm install
npm link
# entre na pasta de um app React/Next onde você quer instalar os componentes
nyx init
nyx list
nyx add button card input
nyx add date-picker data-table questionnaire
# install the complete catalog / instale o catálogo completo
nyx add --all
```

After publishing, `npx @nyx-ui/cli init` and `bunx @nyx-ui/cli add button` run the executable defined in `package.json`. Installed files are placed in `src/components/ui` and do not depend on Nyx at runtime.

`init` creates `nyx.json`, appends a marked block to the global CSS without replacing existing styles, and creates `utils.ts`/`tailwind.config.ts` only when they do not already exist. In projects with an existing Tailwind config, preserve its contents and merge the extensions from `registry/tailwind.config.ts`. Tailwind 4 receives CSS tokens in the theme; `shadow-nyx` and `shadow-nyx-sm` are extensions for Tailwind 3 config files.

## Templates

The local registry is located in `registry/`. `add` accepts multiple names, detects missing Radix UI/Lucide dependencies, and asks before installing them using the package manager indicated by the lockfile. Use `--yes` to install dependencies and `--overwrite` to replace files. `init --yes` uses the conventional paths.

The registry includes all 64 components in the reference catalog plus Search (65 total). Run `nyx list` for the complete list. `nyx add --all` installs the entire catalog; individual installs recursively include local component dependencies (for example, Date Picker brings Calendar, Popover and Button). External dependencies are detected from the registry manifest.

Templates use the `cn` import alias generated by `init` from the selected utils path. Dialog and Hover Card use Radix for focus management, keyboard support, and accessible semantics.

The core Button, Input, and Card templates use the CSS variables from `registry/theme.css` and the `shadow-nyx`, `shadow-nyx-sm`, and `shadow-nyx-lg` utilities. `nyx add button` also offers to install `class-variance-authority`, required by Button. The matching Tailwind 3 config is available at `registry/tailwind.config.ts` (also shipped as `tailwind.config.ts`); Tailwind 4 projects get the token and shadow mappings from the CSS `@theme inline` block.

## Documentation site

The documentation is a Next.js App Router app in `docs-site/`, built with React, TypeScript, and Tailwind CSS. Run `npm run docs:dev` from the repository root to work on the site. The searchable catalog renders the actual templates and provides installation commands, usage examples and editable source. `npm run registry:build` updates `registry/components.json`; docs scripts synchronize templates automatically before development, typechecking and building. `npm run docs:build` builds a static export and copies it into `docs/` for GitHub Pages. The production base path defaults to `/nyx`; set `DOCS_BASE_PATH` when deploying under another path, or set it to an empty string for a custom domain.

## Publishing

The package name `@nyx-ui/cli` requires control of the npm `nyx-ui` scope. If that scope is not yours, change `name` in `package.json` to `@YOUR_NPM_USERNAME/nyx` and update the install commands in this README and `docs-site/app/page.tsx`. Before releasing, run `npm pack --dry-run` and install the resulting package in a separate sample app. Publish from this directory with `npm login` followed by `npm publish --access public`.

# Nyx - BRASIL

CLI para instalar componentes Neo-Brutalistas como arquivos editáveis no seu projeto.

## Desenvolvimento e uso

```sh
npm install
npm link
# entre na pasta de um app React/Next onde você quer instalar os componentes
nyx init
nyx list
nyx add button card input
nyx add date-picker data-table questionnaire
# install the complete catalog / instale o catálogo completo
nyx add --all
```

Depois de publicar, `npx @nyx-ui/cli init` e `bunx @nyx-ui/cli add button` executam a CLI definida em `package.json`. Os arquivos instalados ficam em `src/components/ui` e não dependem do Nyx em runtime.

`init` cria `nyx.json`, anexa um bloco marcado ao CSS global sem substituir estilos existentes e cria `utils.ts`/`tailwind.config.ts` apenas quando ainda não existem. Em projetos com uma configuração Tailwind existente, preserve seu conteúdo e mescle as extensões de `registry/tailwind.config.ts`. O Tailwind 4 recebe tokens CSS no tema; `shadow-nyx` e `shadow-nyx-sm` são extensões para arquivos de configuração do Tailwind 3.

## Templates

O registry local fica em `registry/`. `add` aceita vários nomes, identifica dependências ausentes do Radix UI/Lucide e pergunta antes de instalá-las usando o gerenciador de pacotes indicado pelo lockfile. Use `--yes` para instalar dependências e `--overwrite` para substituir arquivos. `init --yes` usa os caminhos convencionais.

O registry inclui os 64 componentes do catálogo de referência e Search (65 no total). Rode `nyx list` para consultar a lista completa. `nyx add --all` instala o catálogo inteiro; instalações individuais incluem as dependências locais automaticamente (por exemplo, Date Picker instala Calendar, Popover e Button). Os pacotes externos são identificados pelo manifesto do registry.

Os templates usam o alias de importação `cn` gerado pelo `init` a partir do caminho escolhido para utils. Dialog e Hover Card usam Radix para gerenciamento de foco, suporte ao teclado e semântica acessível.

Os templates Button, Input e Card usam as variáveis CSS de `registry/theme.css` e as classes `shadow-nyx`, `shadow-nyx-sm` e `shadow-nyx-lg`. `nyx add button` também oferece instalar `class-variance-authority`, necessária pelo Button. A configuração correspondente do Tailwind 3 está em `registry/tailwind.config.ts` (também incluída como `tailwind.config.ts`); projetos Tailwind 4 recebem os mapeamentos de tokens e sombras pelo bloco CSS `@theme inline`.

## Site de documentação

A documentação é um app Next.js com App Router em `docs-site/`, feito com React, TypeScript e Tailwind CSS. Rode `npm run docs:dev` na raiz do repositório para desenvolver. O catálogo tem busca, filtros, exemplos usando os templates reais, comandos de instalação e código-fonte. `npm run registry:build` atualiza `registry/components.json`; os scripts da documentação sincronizam os templates antes de desenvolver, verificar tipos e compilar. `npm run docs:build` gera a versão estática e a copia para `docs/`, pronta para GitHub Pages. O caminho de produção padrão é `/nyx`; defina `DOCS_BASE_PATH` para outro caminho ou como string vazia ao publicar em domínio próprio.

## Publicação

O nome `@nyx-ui/cli` exige controle do escopo `nyx-ui` no npm. Se o escopo não for seu, altere `name` em `package.json` para `@SEU_USUARIO_NPM/nyx` e atualize os comandos deste README e de `docs-site/app/page.tsx`. Antes de publicar, rode `npm pack --dry-run` e instale o pacote gerado em um app de exemplo. Publique a partir desta pasta com `npm login` e `npm publish --access public`.

## Registry development / Desenvolvimento do registry

```sh
npm run registry:build
npm test
npm --prefix docs-site run typecheck
npm --prefix docs-site run test:components
npm run docs:build
npm pack --dry-run
```

Edit templates in `registry/` and catalog metadata in `scripts/catalog.mjs`. Files in `docs-site/components/ui/` and `docs-site/app/component-data.json` are synchronized from the registry; `docs/` is the generated static export.

Edite os templates em `registry/` e os metadados em `scripts/catalog.mjs`. Os arquivos de `docs-site/components/ui/` e `docs-site/app/component-data.json` são sincronizados pelo registry; `docs/` é a versão estática gerada.
